# #323 plan

**Strategy.** Reuse the existing seam `Singular.Registry.Provider`: replace its record of independent queries with a read interface whose only entry is an acquire step yielding a view (data-model chainpoint-network-magic-era-name-slot-block–provider-read-interface-exactly-one-acquire-operation). The node adapter wraps upstream `withAcquired` from the pinned node-clients, so one view is one LocalStateQuery acquired state and its chain point comes from that state's `LedgerSnapshot`. The in-memory adapter snapshots a mutable chain value at acquire. Builders and CLI commands take a view (or values read from it) instead of a provider; `NodeMode`/`NodeSession` move behind a composition boundary.

**Invariants (each has an observable failure and success).**

- one-view-per-operation-operation-s-preview one-view-per-operation: an operation's preview, fee/outlay decision and built body cite the same view chain point and parameters. Fails if any builder or command path fetches protocol parameters or UTxOs outside the view it was given.
- acquired-not-wrapped-node-view-s-reads acquired-not-wrapped: the node view's reads are served from one acquired ledger state. Fails if a view field issues an independent one-shot query.
- point-identity-view-carries-network-era-slot point-identity: every view carries network, era, slot and block hash; origin is refused. Fails if a write journals a point that differs from its view's point, or if an origin acquire yields a view.
- no-late-entry-parameter-or-utxo-change no-late-entry: a parameter or UTxO change made after acquisition never appears in that operation's preview or body; a fresh acquisition does see it (reached control). Fails if the mutation is unobserved by a fresh acquire (control unreached) or observed by the old view.
- read-cannot-submit-signed-write-no-read read-cannot-submit / signed-only-write: no read type exposes submission; the write capability's argument type is constructible only by signing.
- confinement-ci-source-check-passes-on-head confinement: the CI source check passes on the head and fails on a planted `NodeMode` import in a non-allowlisted `offchain/cli` or `offchain/lib` module.
- model-preserved-conformance-rows-cli-journey-controls model-preserved: conformance rows, CLI journey and controls, journey runners and e2e stay green with unchanged verdicts.
- scope-closed-view-used-after-its-scope scope-closed: a view used after its scope or across a lost connection fails explicitly with a named class, never as empty/absent.
- no-node-call-in-view-no-one no-node-call-in-view: no one-shot node query, submission or confirmation wait runs inside a view scope. Fails as a hang on the shared LocalStateQuery channel; judged by code reading, no CI row (residual).

**Clarification C-1 (operator answer (A-002)).** "Operation" means building one transaction and its preview: one transaction, one view, closed before signing and submitting. Functions that sign and submit one or several transactions take the read interface and acquire one fresh view per transaction; read-backs after confirmation acquire their own view.

**Live boundaries.** Node LocalStateQuery acquire/release; DevNet via `nix run .#devnet` inside `demo1-cli-check`; external node by socket and magic.
