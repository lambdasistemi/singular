# Recovery interfaces

As a maintainer, I want the repair to preserve the existing command interface, so that operators can run the selected part without learning a second recovery protocol.

## Signature boundary

No new or changed product function signature is authorized. The existing recoveryApp name parts abstraction exposes the additional app. CLI_RECOVERY_PARTS remains a space-separated selection of existing scenario names. cli_recovery_controls_check.sh takes one repository-root argument; cli_recovery_controls.sh retains its five executable, blueprint, workspace and repository arguments.

## Observable effects

The cross-wallet selection establishes its own prerequisite through ordinary CLI calls and retains the existing evidence and refusal outcomes. Failed-command reporting adds the command's actual evidence to job output. Any new signature, altered model rule or production repair requires a revised mandate before work continues.
