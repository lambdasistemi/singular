### Order, the model and the pushes

- **The model comes first.** The reviewed model of chunk 2, at an exact revision, is what the producers, bindings and fold of chunk 3 are written against. No consumer is accepted against a model that has not passed its own audit, and each push states the model revision it was built against.
- **One writer at a time.** The model writer and the implementation writer never edit at the same time: the implementation writer stays at a committed boundary while the model is written, or finishes first.
- **The model is its own checkpoint.** It is signed, audited on its own, and then pushed once to a backup branch on the remote, `preserve/529-open-datum-model`, so it does not live only on one disk; that branch triggers no workflow. The model reaches the integration branch only together with chunk 3's consumer migration, and the backup branch is deleted after that push.
- **Chunk 3 pushes once, green.** It is cut into reviewed checkpoints (producers, conformance bindings, fold). No checkpoint is pushed with a conformance row knowingly red, and no legacy behavior is repinned to the new law.
- **The bindings follow the model's output.** The statement header digests in `Controls.hs` are set from the amended model's own output, and replace the old ones only where the product evidence then shows the new law; no check is disabled to make that happen.
- **Every implementation push has its affected journeys green.** Chunks 3 and 4 each name the journeys their changes can affect, and the push is accepted only when those journeys are green.
