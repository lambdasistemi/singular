# Deliver the host and its pairs

As the person who will run the ticket's commands, I want each piece of work named by what it makes true, so that the slice lists show what is done and what is not.

## First slice: the host and the stranger update pair

- [x] host-package-on-shared-sources: the new package builds the executable from its own sources and the shared command-line directory, depending on the registry library, with two added shared lines and none other.
- [x] negative-forms-parsed: the three negative forms parse, every ordinary spelling is handed to the shared parser unchanged, and an unknown spelling is refused as the shared parser refuses it.
- [x] holding-spend-crafting-moved: the controller update, stranger update, tampered update and release outside a fold are written once in the host, not copied from the harness into a second place the shipped binaries use.
- [x] unevaluated-submission-and-verdict: the host signs with the named key file, submits with no local evaluation and reports the node's answer with the failed script hashes and their roles.
- [x] stranger-updates-pair-from-archive: the forbidden update and its control run on a fresh node from the extracted release archive; the refusal is credited only when the node names the application spending contract; the reads before and after are equal.
- [x] judge-from-receipts: every clause is computed from the pair's receipts, and altered receipts change the verdict.
- [x] ordinary-cannot-reach-the-bypass: the ordinary executables refuse the bypass spellings as unknown and contain no host module, read from the built executables, with a positive control on the host.
- [x] no-key-material-printed: a scan of every receipt, output and error for the key bytes the run generated, with a planted positive control.
- [x] new-workflow-and-apps: discovery, one pair part and the ordinary check run in the new workflow through the new Nix apps.

## Delivery and limits

Completion of a slice's list does not assert a merge: delivery waits for the desk's slot and the exact head's hosted checks. Rejection pairs stay pending on protected rejection. The harness copy of the crafting stays until the command-line split cleans it up, and the ordinary build keeps no copy of the bypass. No task counts missing required evidence as passed.
