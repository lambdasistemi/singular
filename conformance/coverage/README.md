# Theorem-coverage gate (issue #80)

A repository-owned command that measures, per Lean obligation, how much executable
implementation coverage exists — and a ratchet that makes silent regression impossible.
Three verdicts, reported separately:

```sh
nix run ./conformance#coverage-gate -- --root . inventory    # reconcile + discover; exit 0
nix run ./conformance#coverage-gate -- --root . ratchet      # per-obligation; 0 = no regression, 2 = regression, 3 = fail-closed
nix run ./conformance#coverage-gate -- --root . completion   # strict; 0 = COMPLETE, 1 = INCOMPLETE (honest), 3 = fail-closed
```

Its test suite (every armed failure control plus real-tree assertions) and the snapshot
verdicts are nix checks: `nix build ./conformance#coverageGateTests ./conformance#coverageGateSnapshot`.

## What each verdict means

- **inventory** — the four theorem manifests are reconciled byte-for-byte against the
  source extraction re-run through `tools/check_model.py`'s `statement_inventory` (reused,
  never re-modeled: there is no hand-maintained registry), and all of `lean/` is scanned
  for theorem declarations with correct identifier handling — dotted (`Inv.fresh_id`),
  primed (`not_mem_of_nodup_append'`), `?`-spelled (`find?_filter_key_ne`) and
  `@[simp]`-attributed forms. Every theorem/lemma keyword occurrence must be accounted
  for by a recognized declaration, so an unknown grammar form fails the scan instead of
  shrinking the denominator. At the frozen base: **192 = 109 manifest-bound + 83
  unclassified**. (The starting inventory's 62 outside the manifests missed 21
  attributed declarations; the unclassified stay in the denominator either way — a
  filename is never evidence of helper status.)
- **ratchet** — the current record against the protected base record, per obligation
  identity (`qualified name + statementSha256`) and per required layer. No offsetting:
  totals are never compared, so new coverage elsewhere cannot pay for a lost guarantee.
  Theorem removal cannot shrink the denominator: the base record carries
  `discoveredPopulation`, and every identity in it must still be discovered.
- **completion** — strict and separate from the ratchet: zero mapping debt, zero
  implementation-layer debt (two distinct executed layers per obligation: a
  property/state-machine check AND an integration-story check, backed by distinct
  executions), zero execution debt (nothing stale, skipped, unexecuted, failing, vacuous
  or non-discriminating), zero unclassified rows, zero stale bindings. It never passes
  because a PR is incremental. CI asserts the honest `INCOMPLETE` verdict explicitly;
  flipping that expectation is claiming completion and is a deliberate act.

## What a coverage record may contain

`record/record.json` (current) and `record/base-record.json` (protected reference, never
written by the gate). Checks bind `obligation@statementSha256`, a layer
(`property`/`state-machine`/`integration-story`), a distinct `executionIdentity`, entry
points, definition digests, and executed evidence (candidate digest over declared paths,
command, seed, cases/discards, then-assertion count, result digest). Validity is computed,
never typed: PASS requires executed evidence, current candidate and definition digests,
a reached precondition (no empty generator, no `Then` with zero assertions, discard ratio
bounded), and a valid discrimination control. Mutation controls establish discrimination;
they never count as a layer. Two checks sharing an `executionIdentity` are one check —
aliases cannot stack into layers.

## Failure controls (each demonstrated against the real gate, in `tests/`)

Remove a theorem mapping; stale a definition digest; rename a row (fail closed); remove a
`Then` assertion; skip a test; present-but-unselected check; alias one execution into two
layers; offset a lost obligation with unrelated new coverage; vacuous generator; excessive
discards; failing behavior relabelled expected (no relabel field exists; a forged PASS
cannot load); weakened invariant (statement edit → stale binding, no inheritance, new
identity starts uncovered); theorem removal (obligation vanished); lying
`discoveredPopulation` (fail closed). Fixture manifests are generated by the real
`tools/check_model.py` extraction.

## Layout

- `singular_coverage/` — the gate: `leanscan` (tokenizer/scanner), `inventory`
  (manifests + discovery), `record` (schema v1), `debt` (three axes, never summed),
  `ratchet`, `completion`, `report`, `gate` (CLI).
- `record/` — current and base records (schema v1, with `discoveredPopulation`).
- `tests/` — the controls; `tests/fixtures.py` builds synthetic lean trees with manifests
  generated by the real extraction.
- `evaluation/` — the bounded `tasty-bdd` feasibility evaluation (recommendation pending
  owner/user review; not delivered coverage).
- `correspondence/` — two rendered human-correspondence views: a ground instance
  (`naming_occupied_key_refuses_duplicate.md`) and the quantified equivalence under load
  (`fold_iff.md`, whose converse is contradicted by the compiled validator — F-002, held
  for user ruling Q-002). Review surfaces for the user; not delivered coverage.

## Limits, stated

Discovery is lexical, not proof-term: reference counts are leads and never classify or
exclude. The base record is protected by review (it lives in the repo; the ratchet never
writes it; CI runs the gate on every conformance/lean/tools change) — an explicit,
reviewed rebase of the base is the only way it moves. The gate reads `--root` at run time;
the nix checks run it against a hash-bound snapshot of `lean/`, `tools/` and this
directory. Strict completion additionally requires the release/milestone wiring that the
root flake and CI own — not yet wired (owner-confirmed scope required); until then
`completion`'s verdict is the acceptance input, not the release gate itself.
